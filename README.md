# Inventory Management System

A Flask REST API for managing a small retail inventory, with a command-line
interface and OpenFoodFacts integration for looking up and importing product details.

## Features

- CRUD endpoints for inventory items (GET, POST, PATCH, DELETE)
- Helper routes: search by name and a health check
- OpenFoodFacts lookup by barcode or name, and import of a product into the inventory
- Menu-driven CLI with input validation and friendly error messages
- Unit tests for the API, the external API client and the CLI (all external calls are mocked)

## Installation and Setup

Requires Python 3.9 or newer.

```bash
git clone https://github.com/lewismacharia1-coder/inventory-api.git
cd inventory-api
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Running the Project

**1. Start the API** (runs in Flask debug mode on http://127.0.0.1:5000):

```bash
python app.py
```

**2. Start the CLI** in a second terminal (activate the virtual environment there too):

```bash
python cli.py
```

**3. Run the tests:**

```bash
pytest -v
```

## Data Model

Inventory items are stored in a Python list in `data.py`. The data lives in
memory, so it resets whenever the server restarts.

| Field | Type | Notes |
|---|---|---|
| id | integer | Generated by the server |
| product_name | string | Required |
| brands | string | Optional |
| ingredients_text | string | Optional |
| barcode | string | Optional |
| price | number | 0 or more (default 0.0) |
| stock | integer | 0 or more (default 0) |

## API Endpoints

| Method | Endpoint | Description | Success | Errors |
|---|---|---|---|---|
| GET | /health | Check the server is running | 200 | |
| GET | /inventory | List all items | 200 | |
| GET | /inventory/<id> | Get one item | 200 | 404 |
| POST | /inventory | Add an item | 201 | 400 |
| PATCH | /inventory/<id> | Update the fields sent | 200 | 400, 404 |
| DELETE | /inventory/<id> | Remove an item | 200 | 404 |
| GET | /inventory/search?name= | Search items by name | 200 | 400 |
| GET | /external/lookup?barcode= or ?name= | Look up OpenFoodFacts (read-only) | 200 | 400, 404, 502 |
| POST | /inventory/import/<barcode> | Fetch from OpenFoodFacts and add to inventory | 201 | 400, 404, 409, 502 |

### Examples

Add an item:

```bash
curl -X POST http://127.0.0.1:5000/inventory \
  -H "Content-Type: application/json" \
  -d '{"product_name": "Rice 1kg", "brands": "Pishori", "price": 2.5, "stock": 40}'
```

```json
{
  "barcode": "",
  "brands": "Pishori",
  "id": 4,
  "ingredients_text": "",
  "price": 2.5,
  "product_name": "Rice 1kg",
  "stock": 40
}
```

Update the stock of item 1:

```bash
curl -X PATCH http://127.0.0.1:5000/inventory/1 \
  -H "Content-Type: application/json" \
  -d '{"stock": 30}'
```

Delete item 2:

```bash
curl -X DELETE http://127.0.0.1:5000/inventory/2
```

```json
{"message": "Item 2 deleted"}
```

Look up a product on OpenFoodFacts (the values come from OpenFoodFacts):

```bash
curl "http://127.0.0.1:5000/external/lookup?barcode=3017620422003"
```

Import it into the inventory with a price and stock:

```bash
curl -X POST http://127.0.0.1:5000/inventory/import/3017620422003 \
  -H "Content-Type: application/json" \
  -d '{"price": 5.5, "stock": 12}'
```

Errors are always JSON, for example `{"error": "Item not found"}`.

## CLI Usage

```
==== Inventory Manager ====
1. View all items
2. View item details
3. Add new item
4. Update price or stock
5. Delete product
6. Search inventory
7. Find item on OpenFoodFacts
0. Quit
```

- **Add:** the CLI asks for each field and keeps asking if the price or stock is not a valid number.
- **Update:** leave a field blank to keep its current value.
- **Delete:** asks for confirmation (y/n) first.
- **Find on OpenFoodFacts:** search by barcode or name, then choose a result to import.
- If the server is not running, the CLI shows a clear message instead of crashing.

## Testing

```bash
pytest -v
```

- API tests use Flask's test client with a fresh inventory for every test.
- OpenFoodFacts calls are mocked with `unittest.mock`, so tests never use the network.
- CLI tests mock keyboard input and HTTP requests.

## Error Handling

| Situation | Response |
|---|---|
| Invalid or missing input | 400 with a clear message |
| Item not found | 404 |
| Barcode already in the inventory | 409 |
| OpenFoodFacts unreachable or failing | 502 |
